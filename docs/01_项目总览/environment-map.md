## 1. 文档目的
明确开发/测试/预发/生产四类环境的访问方式、数据隔离策略与发布流转规则。

## 2. 业务/技术背景
依赖 project-overview.md 了解项目边界，依赖 08_部署运维 了解部署细节。

## 3. 核心规则 & 约束（重点）
- [强制] 四类环境（开发/测试/预发/生产）必须物理或逻辑隔离，禁止混库。
- [强制] 生产环境仅允许通过 release 分支 + 审批后发布，禁止直接部署。
- [建议] 预发环境数据尽量使用脱敏的生产镜像，保证验证真实性。

## 4. 详细设计/内容
### 4.1 环境清单
| 环境 | 用途 | 访问地址 | 数据来源 | 发布方式 |
|------|------|----------|----------|----------|
| 开发 | 本地编码与单测验证 | 本地进程 `oaip run`（localhost） | 本地 Turso 文件 `./data/dev.db` | feature 分支直连本地，免发布 |
| 测试 | 自动化集成测试 | CI Runner 内 `oaip run` | CI 临时 Turso（内存/临时文件，每次重建） | dev 分支合入触发 CI |
| 预发 | 发布前回归与演示 | 内网 `staging.oaip.local` | 独立 Turso 实例，脱敏生产镜像数据 | release/vx.x.x 分支部署，人工验证 |
| 生产 | 实际运行与对外服务 | 生产域名 / 内网托管 | 生产 Turso（libSQL 托管或本地加密文件） | main + git tag，审批 + 双人复核发布 |

### 4.2 环境流转规则
1. 开发自 feature 分支提交至 dev
2. dev 经测试通过后合入 release/vx.x.x
3. release 经预发验证后合入 main 并打 tag


## 5. 风险点 & 注意事项
- 生产环境误操作不可逆，必须双人复核。
- 环境配置差异可能导致预发通过但生产失败。
